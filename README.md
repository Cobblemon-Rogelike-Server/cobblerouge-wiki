# CobbleRouge 서버 위키

서버 작물 56종, 성장 촉진제, 전용 나무 8종, 목재 세트와 장식 블록을 모두 찾아볼 수 있는 한국어 정적 위키입니다. 던전의 입장·여섯 종류의 방·전투·기믹·보상과 탐험단의 가입·의뢰·금고·혜택·합동 탐사 안내까지 총 114개 항목을 제공합니다.

최신 작물 이미지 683장과 던전·탐험단 그림 9장, 총 692장을 사용합니다. 성장 단계, 심는 환경, 가격과 조합법을 검색할 수 있습니다.

## 새 플레이어를 위한 읽기 흐름

홈은 **시작 안내 → 던전·섬 생활·탐험단 선택 → 한 번의 모험 흐름 → 자주 묻는 질문** 순서입니다. 기존 도감과 문서 주소를 보존하면서 처음 읽을 문서와 다음에 읽을 문서를 안내합니다.

- [처음 온 모험가를 위한 시작 안내](content/guides/getting-started.md): 파티·코스트, 입장 시 보관되는 것, 지도 우클릭, 보스와 정산, 다음 모험을 순서대로 설명합니다. 서버 주소·스타팅 포켓몬처럼 확인하지 못한 운영 정보는 만들지 않습니다.
- 진행 다이어그램은 네 단계를 눌러 읽는 탭입니다. 키보드 방향키·Home·End로도 이동하며 각 단계에서 원문 도감으로 이어집니다. 실제 게임 진행도나 실시간 API가 아닙니다.
- 긴 문서는 제목 구조에 따른 자동 목차와 특정 절로 바로 연결하는 주소(`#/article/dungeon-entry?section=section-2`)를 제공합니다. 문서에는 읽기 위치 표시, 링크 복사와 관련 문서도 연결합니다.
- 검색은 상단에 항상 유지합니다. `Ctrl/Cmd K`로 열고 이름·아이템 ID·본문을 검색하며 분류로 좁힙니다. 기존 런처 연동 주소 `#/search?q=유전자`도 유지합니다.
- ‘나중에 읽기’, 최근 본 문서, 시작 안내의 읽기 체크는 **현재 브라우저의 localStorage에만** 저장합니다. 계정·게임 진행도와 연동하지 않고 서버로 보내지 않습니다. 브라우저 저장소를 사용할 수 없어도 탐색·검색은 동작합니다. 읽기 체크는 가이드에서 초기화할 수 있습니다.
- 모바일의 접는 목차·메뉴·표의 가로 스크롤·키보드 포커스·본문 건너뛰기·움직임 줄이기를 지원합니다. 기본 본문은 모바일에서도 15px로 표시합니다.

게임 이미지 692장은 그대로 사용합니다. 홈의 `assets/editorial/islands.webp`는 이 위키를 위해 AI로 만든 별도 콘셉트 일러스트로, 게임 화면·실제 맵·구현된 월드의 증거가 아닙니다. 화면에도 콘셉트 일러스트임을 표시합니다. 외부 폰트·이미지 CDN·분석 스크립트를 사용하지 않습니다.

## Vercel에 배포하기

1. Vercel의 **Add New → Project**에서 `Cobblemon-Rogelike-Server/cobblerouge-wiki`를 가져옵니다.
2. **Framework Preset: Other**, **Root Directory: 저장소 루트**로 둡니다.
3. 저장소의 `vercel.json`이 **Build Command: `python3 scripts/build.py`**, **Output Directory: `dist`**를 지정합니다. Install Command는 비워 둡니다.
4. **Deploy**를 누릅니다. 환경 변수, 토큰, 데이터베이스는 필요하지 않습니다.
5. 사용자 도메인은 배포 후 **Project Settings → Domains**에서 추가합니다. 클라이언트의 위키 버튼에는 확정된 사이트 주소를 기본 브라우저로 여는 동작을 연결하면 됩니다.

Vercel Git 연동 후 `main`의 변경 사항은 자동으로 배포됩니다. GitHub Pages 배포 워크플로는 포함하지 않습니다.

## 로컬에서 확인하기

Python 3.10 이상만 있으면 됩니다. 외부 패키지나 비공개 저장소 인증은 필요하지 않습니다.

```sh
python3 scripts/build.py
python3 -m http.server 8000 --directory dist
```

http://localhost:8000 에서 확인합니다. 상대 주소와 해시 라우팅을 사용해 항목 링크를 새로고침해도 유지합니다.

## 자동 검증

```sh
python3 scripts/build.py
node --check app.js
CHROMIUM_PATH=/usr/bin/chromium node scripts/check-ui.mjs
```

브라우저 검증에는 Node.js 24 이상과 Chrome/Chromium이 필요하며 npm 의존성은 없습니다. `CHROMIUM_PATH`는 설치된 브라우저의 경로입니다. 테스트는 임시 프로필과 로컬 서버를 사용하며 `WIKI_UI_ARTIFACTS`로 화면 PNG 저장 위치를 지정할 수 있습니다.

빌드는 작물 56종·문서 ID 중복·원본 PNG 692장과 모든 문서 이미지 참조를 검증합니다. 실제 브라우저 검사는 전체 114개 문서와 기존 내부 링크, 검색·분류·잘못된 주소, 읽기 체크·문서 저장의 새로고침 보존, 저장소 비활성 상황, 다이어그램 키보드 조작, 절 바로가기, 모바일 메뉴, 320/390/800/1440px의 가로 넘침과 배포 CSP를 확인합니다. `.github/workflows/check.yml`에서 push·PR 때 같은 검사를 실행하고 화면을 아티팩트로 남깁니다.

## 내용 수정하기

- `content/guides/`: 첫 던전 준비부터 재배와 섬 꾸미기까지 안내. 한국어 Markdown 파일을 추가하면 길라잡이 목록에 들어갑니다.
- `content/dungeon/`: 입장 준비, 여섯 종류의 방, 고대 금화와 지도, 전리품, 스텟, 전투와 음식, 기믹, 종료·재접속과 엔드리스 안내 19개. 유전자 조작소는 종합 비교와 특성·기술·종족값의 독립 문서로 구성하며, 레벨 계산 비교 문서에는 야생·트레이너·보스의 공식과 예시를 정리합니다.
- `content/guild/`: 결성과 가입, 직책, 채팅, 주간 의뢰, 레벨·금고, 혜택, 순위, 합동 탐사, 거점, 표식·망토·도전과제 안내 10개.
- `content/작물.md`: 재배 환경별 작물 56종과 성장 촉진제. `###` 제목이 개별 작물입니다.
- `content/전용_나무.md`: 나무 크기, 열매, 원목·목재·판자·잎·묘목.
- `content/목재_세트.md`: 계단·반 블록·울타리·울타리 문·문·다락문·압력판·버튼·표지판·매다는 표지판의 조합법.
- `content/장식_블럭.md`: 더미·초가지붕·버섯 갓·화분·등·꽃잎·연잎·바구니·말림 장식.
- `assets/images-*.json`: 문서에 쓰이는 원본 PNG 692장을 Base64로 손실 없이 저장한 이미지 묶음. 빌드 시 `dist/images/`에 원래 파일 그대로 복원합니다. 3D 렌더는 PNG이며 회전 가능한 3D 뷰어는 아닙니다. 게임에서 평면인 씨앗·묘목은 평면 그림으로 표시합니다.
- `scripts/build.py`: 문서를 HTML과 검색 데이터로 변환하고, 작물 수·항목 ID·이미지 참조를 검증합니다.
- `app.js`, `styles.css`, `index.html`: 입문 홈, 진행 다이어그램, 이름·아이템 ID·본문 검색, 재배 환경 필터, 목차·다음 문서, 기기별 읽기 기록, 모바일 메뉴와 상세 화면.

`dist/`는 빌드 결과이므로 Git으로 관리하지 않습니다. 별도 SPA 리라이트나 Node.js 의존성 설치가 필요하지 않습니다.

### 그림 갱신

기존 PNG를 꺼내 편집할 경우 `python3 scripts/image_assets.py --extract-to work`를 실행합니다. `work/images/` 아래의 디렉터리 구조와 파일명을 유지해 그림을 갱신한 뒤 `python3 scripts/image_assets.py --source work/images`로 이미지 묶음을 다시 만드세요. 새 원본 이미지 폴더가 있으면 `--source`에 그 폴더를 바로 지정해도 됩니다. 이 과정은 PNG의 바이트를 변환하거나 다시 렌더링하지 않습니다. 마지막으로 `python3 scripts/build.py`를 실행해 모든 참조를 검증하세요.
